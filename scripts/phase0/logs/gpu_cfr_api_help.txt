NAME
    gpu_cfr.games.hunl_river - HUNL river endgame GameSpec builder.

DESCRIPTION
    Models a single-street river subgame as a chance-rooted EFG: the root chance
    node deals one (hand0, hand1) combination from the two players' ranges
    (uniform over non-conflicting pairs), followed by a one-street betting tree
    (check / bet / fold / call, no raises — the structure used by
    project_1_1/tree.py). Payoffs are in the same chip units as ``pot``/``stack``.
    
    Payoff convention (player 0 view): the pot before river action is split
    half/half as sunk contributions, so winning a showdown or a fold is worth
    ``pot/2`` plus whatever additional chips the opponent put in.

FUNCTIONS
    build_default_hunl_river_game() -> 'GameSpec'
        Build the registered benchmark instance of the river endgame.
        
        The build allocates ~137k NodeSpec objects (tens of seconds), so the
        deterministic default instance is cached; callers must not mutate it.
    
    build_hunl_river_game(board: 'Sequence[str]', pot: 'float' = 20.0, stack: 'float' = 100.0, bet_fractions: 'Sequence[float]' = (0.5, 1.0), num_hands_per_player: 'int' = 100, seed: 'int' = 0, hands0: 'Sequence[Hand] | None' = None, hands1: 'Sequence[Hand] | None' = None, name: 'str' = 'hunl_river') -> 'GameSpec'
        Build a HUNL river endgame as a chance-rooted GameSpec.
        
        Args:
            board: Five board cards as strings, e.g. ("Ks", "Js", "Th", "7d", "2c").
            pot: Total pot (chips) before river action.
            stack: Effective stack behind (same for both players); bets are capped
                at this amount.
            bet_fractions: Bet sizes as fractions of the pot.
            num_hands_per_player: Range size sampled uniformly per player (ignored
                for a player whose explicit hand list is given).
            seed: Seed for the deterministic range sampling.
            hands0: Optional explicit range for player 0 (overrides sampling).
                Hands are sorted (low, high) card-id pairs as produced by
                enumerate_hunl_hands.
            hands1: Optional explicit range for player 1 (overrides sampling).
            name: GameSpec name.
        
        Returns:
            A two-player zero-sum GameSpec.
        
        Raises:
            ValueError: If the board is invalid or the ranges admit no valid deal.

Help on module gpu_cfr.games.hunl_turn in gpu_cfr.games:

NAME
    gpu_cfr.games.hunl_turn - HUNL turn endgame GameSpec builder (Libratus-style two-street subgame).

DESCRIPTION
    Extends the river endgame of :mod:`hunl_river` by one street: the root chance
    node deals one (hand0, hand1) combination, a turn betting street follows the
    same no-raise grammar, and every betting line that does not end in a fold
    reaches a second chance layer that deals one of the remaining river cards
    (uniform over the 52 - 4 - 4 = 44 cards unseen by either player), followed by
    a river betting street whose bet sizes are fractions of the grown pot capped
    by the remaining stack.
    
    Payoff convention (player 0 view) matches hunl_river: the pre-turn pot is
    split half/half as sunk contributions, so a fold forfeits the folder's sunk
    chips (half-pot plus their turn contribution on the river street) and a
    showdown is worth the winner's sunk-plus-matched total.

NAME
    gpu_cfr.solvers.update_rules - Regret matching update rules.

DESCRIPTION
    Every rule here is graph-capturable: the per-iteration scalars are read from a
    device-side iteration counter (``t``) rather than a host float, so a captured
    CUDA graph replays a *changing* discount instead of freezing the coefficients
    that happened to hold at capture time.
    
    Two conventions are pinned deliberately, because both have a second spelling in
    the wild that gives different numbers:
    
    Discount placement
        Accumulators are discounted *before* the iteration's new mass is added, as
        in Brown & Sandholm's recursions. ``discount`` therefore runs at the top of
        an iteration, not in ``after_iteration``.
    
    Average-strategy weighting
        Two spellings exist and they are *not* interchangeable. DCFR and PCFR+ use
        the multiplicative recursion ``C <- C * ((t-1)/t)**gamma + pi * sigma``
        (Brown and Sandholm Eq. 3; what PokerRL and DDCFR implement). OpenSpiel
        instead accumulates ``C += pi * sigma * t**gamma``. They agree for a fixed
        ``gamma`` but diverge sharply once ``gamma`` varies with ``t``: under the
        recursion a schedule starting at ``gamma=30`` concentrates over 90% of the
        average's mass in the final handful of iterations, effectively discarding
        the average. HS-DCFR's published schedules are calibrated against
        OpenSpiel's power form -- its reference implementation drives
        ``discounted_cfr.DCFRSolver`` directly -- so that rule uses the power form
        and the fixed-gamma rules keep the recursion. Each rule therefore declares
        its own convention rather than inheriting one.
