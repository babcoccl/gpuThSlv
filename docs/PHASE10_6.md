# Phase 10.6 — remove request-path self-healing; close review warnings

Date: 2026-11-18. Status: done (gate below).

Everything in the test-case section below was written **before**
implementation and is not revised after seeing results.

## Scope

1. **No request-path writes.** `get_node` order: validate the history
   (chance/terminal rejected with 422 *before* any table work) → payload
   cache → node-EV table (persisted file, else computed in memory once
   per job under a per-job single-flight lock, kept in the bounded
   index/table LRU). `regen_locks`/`_regen_node_evs` and the
   request-path `write_node_evs` call are deleted; a declined
   `evs.npz` serves live-computed values and never writes.
2. **One writer.** `Scheduler._export_node_evs` at job completion is the
   only evs.npz writer; crash tests (ENOSPC mid-write, fsync,
   os.replace; with/without prior file) assert no empty *or partial*
   destination file — the zero-byte assertion is added.
3. **Migration command** `python -m holdem_solver.api.regen_evs
   [--job ID | --all]`: regenerates persisted evs files for jobs whose
   strategy file still exists, skips expired jobs, idempotent, writes
   through `write_node_evs` (the single atomic writer). The orphan
   sweep deletes companion `*.evs.npz` files whose strategy file no
   longer exists regardless of mtime.
4. **Null parity.** Persisted and live `node_values` agree including
   nulls: where `opp_mass` is zero (own reach but no compatible
   opponent reach) the persisted path serves null too — `load_node_evs`
   drops zero-mass combos (they decode as zeros, not omissions).
5. **Tolerance.** One per-cell rule `|diff| <= 1e-12 * max(1, |ref|)`
   in `compare_cells`, scope text, tests and the doc guard — the
   either-bound whole-check form is dropped. `evec_all_nodes.json` and
   docs report the worst-*absolute* cell (value, ref, relative) and the
   worst-*relative* cell separately; the "2.0e-10 / 57,000" statement
   is corrected (that cell's relative error is ~3.5e-15; 2.3e-14 is a
   *different* cell — the worst-relative one).
6. **Import boundary walker.** Bare sibling imports
   (`from evs_fixture import ...`, `import mid`) resolve against the
   importing file's directory plus any `sys.path` entries configured
   by `conftest.py`/`pytest.ini` (`pythonpath`). Every import is
   classified stdlib / installed third-party / local; an unresolved
   import fails. The negative test is built through the same indexer
   production uses (no injected aliases) and includes a bare-sibling
   edge reaching `holdem_solver.api`.
7. `docs/PROGRESS.md` gains the 10.6 entry; `PHASE10_5.md` notes are
   updated where behavior changed (self-heal removed, either-bound
   dropped).

## Test cases (fixed)

### 1 — request path never builds on rejected histories or cache hits

In `tests/test_api_phase9.py`, with `export_node_evs` wrapped in a
counter and the `evs.npz` file deleted:

- `test_node_chance_terminal_no_table_build`: `GET /node` on a chance
  history and on a terminal history returns 422 and performs **zero**
  `export_node_evs` calls — even though the job has no usable file.
- `test_node_cache_hit_no_table_build_readonly_dir`: after a first
  `/node` warms the payload cache, the data directory is made
  read-only; a repeat `/node` returns 200 with **zero** table builds
  (the payload cache is consulted before the table).
- `test_node_first_requests_single_flight_in_memory`: N concurrent
  first `/node` requests after a declined file produce exactly one
  `export_node_evs` call, all 200s, and **no** `evs.npz` write
  (`write_node_evs` is never called from the request path — asserted
  by patching it to raise).
- The former self-heal tests are renamed/inverted: a declined file
  stays declined on disk after `/node` serves live values
  (`test_node_declined_file_not_rewritten` per decline kind:
  missing/corrupt/stale/v1 — served values identical to live compute,
  nothing written back).
- Terminal histories move from 404 to 422 on `/node`; `/tree` keeps
  its 404.

### 2 — crash tests assert a non-empty destination

`tests/test_api_evec.py::_assert_crash_leaves_nothing` gains: when the
destination exists after a failed export it is neither zero-byte nor a
truncated prefix of the valid payload — i.e. `size > 0` and the bytes
equal a previously valid file (byte-identical for the prior-file
cases; absent otherwise). The mutation test is unchanged.

### 3 — regen_evs + orphan sweep

New `tests/test_api_regen_evs.py` (`.venv-api`):

- `test_regen_evs_all_and_by_job`: a job whose `evs.npz` is deleted is
  regenerated by `--all` and `--job ID`; the file reloads through
  `load_node_evs` (format v2) and serves identical `/node` values.
- `test_regen_evs_skips_expired`: a job marked `strategy_expired_at`
  (retention ran) is skipped — nothing written.
- `test_regen_evs_idempotent`: two runs leave a valid file; the second
  run reports the job again (recomputed + rewritten through the atomic
  writer) and the loaded table is identical.
- `test_regen_evs_concurrent_retention`: retention cleanup deleting
  the strategy concurrently does not crash the regen and does not
  write an `evs.npz` for the expired job.
- `test_orphan_sweep_deletes_companion_without_strategy`: an
  `*.evs.npz` whose `strategy-*.npz` does not exist is removed by
  `cleanup_strategies` even when fresh (mtime now) — and a companion
  of an existing strategy is kept.

### 4 — null parity

In `tests/test_api_evec.py`:

- `test_persisted_zero_opp_mass_serves_null`: on a blocker spot (dead
  cards leave own combos with zero compatible opponent reach) and on a
  turn spot, `node_values` served from the persisted table equals the
  live walk **including nulls**: every served cell compared with
  `compare_cells`-style accounting (compared == expected, no omitted,
  no extras), and the affected combos carry `action_evs`/`ev` nulls in
  both paths.

### 5 — tolerance single rule + worst cells

`compare_cells` returns per-cell worst records: `worst_abs`
`{combo, action, got, ref, diff, rel}` and `worst_rel` (same fields).
`evec_all_nodes.py` reports both per check and a check passes iff
`max_rel_diff <= 1e-12` (the absolute column stays informational).
`tests/test_compare_cells.py` gains: a cell inside the relative bound
but over a large absolute value passes the rule computation; the worst
cells are identified correctly (worst-absolute ≠ worst-relative case).
`check_suites.py` asserts `max_rel_diff <= 1e-12` and that the
`worst_abs_cell`/`worst_rel_cell` fields are present and consistent
with `max_abs_diff`/`max_rel_diff`. Docs state worst-absolute cell
`2.0e-10` at `|ref| ≈ 5.7e4` → `3.5e-15` relative and the separate
worst-relative cell `2.3e-14`.

### 6 — import boundary walker

`tests/test_import_boundary.py` reworked:

- `_imports` resolves bare top-level names (`import helper`,
  `from evs_fixture import ...`) against the importing file's own
  directory first, then `sys.path` entries configured by
  `conftest.py`/`pytest.ini` (`pythonpath = ...`), then the repo
  package roots.
- `classify_import(name) -> "stdlib" | "thirdparty" | "local"`: stdlib
  via `sys.stdlib_module_names` (3.10+) / a builtin+stdlib fallback on
  3.9; local via module-file resolution; third-party via
  `importlib.util.find_spec` on the running venv. Any import that is
  none of the three fails the suite (restricted to files whose
  declared venvs include the running venv).
- `test_declared_venv_matches_imports_negative` is rebuilt through the
  real indexer: a tmp directory is treated as an added root (the same
  resolution a `pythonpath` entry gets) containing `helper.py`
  (`from holdem_solver.api import evec`), `mid.py` (`import helper`
  — a bare sibling edge), and `script.py` declaring `.venv-engine`;
  the walk must flag `script.py` reaching `holdem_solver.api` via
  `mid -> helper`.
- New `test_unresolved_import_fails`: a tmp file importing a
  nonexistent top-level name is reported unresolved.
- Real coverage: the repo's own bare-sibling imports between tests
  (`from test_evwalk import ...`, `from test_client_fake import ...`)
  resolve as local through the file's directory.

## Results

- Self-heal removal: all four decline kinds serve identical values
  from an in-memory table without touching the file; 8 concurrent
  first requests produce exactly one `export_node_evs` call and zero
  `write_node_evs` calls; chance and terminal histories 422 with
  zero table builds on a fileless job; a payload-cache hit builds
  nothing under a read-only data dir.
- Crash tests: zero-byte destination assertions added; mutation
  verified (writer leaving a zero-byte dest fails the crash test).
- `regen_evs`: regenerates live jobs, skips expired and
  missing-strategy jobs, idempotent (byte-identical rewrite), loses
  the race against a concurrent retention cleanup (nothing written);
  `--all` reports regenerated/skipped counts.
- Orphan sweep: a fresh `.evs.npz` companion with no strategy file
  is deleted; a fresh `.npz` orphan stays protected by age.
- Null parity: blocker spot and turn spot both reach
  `compared + null_pairs == expected` with `null_pairs > 0` and
  identical values/nulls on every served cell.
- `evec_all_nodes.json` regenerated under the single per-cell rule
  with `worst_abs_cell` / `worst_rel_cell` per check: river agg
  worst-abs 1.96e-10 (rel 9.9e-15) / worst-rel 2.29e-14; turn-chance
  agg 8.60e-13 / 4.57e-13; raisecap2 4.09e-12 / 1.17e-13 — all
  within `1e-12 * max(1, |ref|)`.
- Import boundary: bare-sibling imports resolve via the importing
  file's directory and configured sys.path roots; every import
  classified stdlib/third-party/local; unresolved imports report
  file+name; the negative test reaches `holdem_solver.api` through
  the production indexer.
